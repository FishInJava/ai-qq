# 主动陪伴型 AI 聊天助手 — 设计与执行计划

> 状态：决策已封板，等待开工
> 版本：v1（拷问六轮后定稿）
> 定位一句话：**一个会自己找你说话的 AI 角色，用你从酒馆带过来的角色卡。**

---

## 1. 核心赌注

酒馆（SillyTavern）的核心是**交互**——你一句，她一句，她只在你说话之后才存在。
本产品的核心是**主动陪伴**——她有自己的时间线、自己的心情、自己「今天不想说」的权利。

不可替代的理由只选一条：

> **把主动性的真实感做到现有产品没做到的程度。**

角色卡生态（V2 兼容）是护城河，不是主轴。因为单靠兼容撑不起一个产品——用户会想「那我直接用酒馆不就行了」。

## 2. 已封板决策（不再讨论）

| # | 决策项 | 结论 | 理由（一行） |
|---|---|---|---|
| D1 | 定位 | 单用户 + 本地运行，无账号/计费/审核 | 先验证「她主动找你时你会不会心动」，不是「一百个人会不会付费」 |
| D2 | 角色卡 | V2 读写全兼容 + `extensions` 原样透传；正则脚本 / STscript 导入时忽略并提示 | 「拖进来就能用」是爽点，脚本引擎是深坑 |
| D3 | 会话结构 | **一卡一窗口**，不可并行时间线 | 多线会让记忆分裂，与「她是真人」冲突 |
| D4 | 运行时 | **node 常驻进程**；html 页面只是 UI，关闭页面不影响调度 | 主动性的定义是她「在你没看的时候」行动 |
| D5 | 三态 | Active / Paused / Dormant（见 §5） | 两个不活跃入口在叙事上是不同的事，混态会穿帮 |
| D6 | Dormant 表现 | **禁止任何系统腔提示**（不许出现「额度已用尽」） | 一旦出现系统口吻，幻觉立刻破功，她从人变回软件 |
| D7 | 真人判据 | 4 条全部进验收测试（见 §9） | 这是全产品唯一可测的东西 |
| D8 | 世界时钟 | 1:1 真实时间；离线**不补演**；重启后**不主动开口**，等你先说 | 用户选择最简单版本 |
| D9 | 记忆 | SQLite 事实表 + 每 20 轮摘要 + 关键词检索；**不上向量库** | 「翻旧账」要的是时间锚点，不是语义相似度 |
| D10 | 调度 | 20–40 分钟决策 tick（小上下文 + 投币决定是否调用大模型）+ 6 小时静默硬触发 | tick 是「她像活的」的发动机；到点必发的是推送 |
| D11 | 主动消息内容 | 每天离线生成 2–3 条「她的生活事件」落库；**每条主动消息必须锚定**（今日事件或旧事实） | 禁止无锚点的「在干嘛呢」，这是产品死不死的关键 |
| D12 | 打扰预算 | 全局每日 5 条、单角色每日 2 条；角色之间**竞争**你的注意力 | 竞争产生「今天她抢到了开口机会」的真实感 |
| D13 | 联网 | 模型**无权**联网；pipeline 每天定时抓白名单三类（本地天气 / 节日日期 / 一条新闻头条），限次 | 无人监督的自主搜索＝跑偏 + 账单，且失败是静默的 |
| D14 | Token | 单窗口总额；70% 时非对话层提示（角标，不是她说话）；可手动续额；耗尽即 Dormant | 用户选择最简单版本 |
| D15 | 主动消息上下文 | 必须比对话更短（人设 + 近期摘要 + 今日事件），不喂全史 | 否则钱全花在「早安」上 |
| D16 | 明确不做 | 向量库 / 多角色并行 / 脚本引擎 / 推送通道 / 多用户 / 静默期 / 去重 | 砍掉的都是扩展性，留下的是「像人」 |

## 3. 已接受的风险登记（不加实现，出事直接翻这里）

| R# | 风险 | 触发场景 | 现成补丁（约 10 行） |
|---|---|---|---|
| R1 | **冷启动沉默** | 每次开机/重启后她不主动说话，像个刚认识的人 | 配置项 `cold_start_proactive = false`，改一个值即可开启 |
| R2 | **无静默期穿帮** | 你说「我去开会了」，20 分钟后收到「在干嘛呢」——**第一次用就会撞上** | 「最后一条消息 + 90 分钟不打扰」时间戳规则 |
| R3 | **复读机感** | 两周内重复「在干嘛呢」，这是复读机的第一来源 | `proactive_log` 前 8 字指纹硬去重 + 附上最近 10 条禁重主题 |

> 这三条若以后让你觉得「她变假了」，不用重新论证，直接打补丁。

## 5. 状态机

### 5.1 三态定义

| 状态 | 触发 | 她的行为 | 你的行为 |
|---|---|---|---|
| **Active** | 你点「开始聊天」 | 会主动发消息；有问必答 | 自由对话 |
| **Paused** | 你手动关闭活跃开关 | **不发主动消息**；你找她她照常回；叙事上是「在忙 / 睡了 / 这两天不方便」 | 仍可对话 |
| **Dormant** | 窗口 token 额度耗尽 | **不能生成新话**；只能给已缓存的极短回应或沉默 | 可续额，续额后回到 Active |

### 5.2 转换表

| 从 | 事件 | 到 |
|---|---|---|
| — | 选择角色点「开始聊天」 | Active |
| Active | 用户关闭活跃开关 | Paused |
| Paused | 用户打开活跃开关 | Active（需时间断层感，不能无缝续上） |
| Active / Paused | token 额度 ≤ 0 | Dormant |
| Dormant | 用户续额 | Active |
| 任意 | 进程重启 | 保持原状态，但**不主动开口**（R1） |

### 5.3 硬红线
- Dormant 下不得输出任何系统口吻文本（余额、配额、错误码）。
- 额度 70% 的提示只允许出现在 UI 层（角标/进度条），**不得由角色说出**。
- Paused → Active 时必须处理时间断层。

## 6. 数据模型（SQLite，字段清单，非最终 DDL）

单一文件 `data/companion.db`。时间统一存 UTC ISO8601。

| 表 | 关键字段 | 用途 |
|---|---|---|
| `characters` | id, name, card_json（V2 原始）, extensions_json, avatar_path, imported_at, source_hash | 角色卡原样留存，便于无损导出 |
| `sessions` | id, character_id（唯一）, state（active/paused/dormant）, token_limit, token_used, created_at, last_user_msg_at, last_proactive_at | 一卡一会话，含额度账本 |
| `messages` | id, session_id, role（user/char/system_note）, content, is_proactive, anchor_type（event/fact/none）, created_at, tokens | `anchor_type = none` 的主动消息视为违规 |
| `facts` | id, session_id, subject（user/char/world）, key, value, valid_from, valid_to, status（pending/done/dropped）, source_msg_id | 支撑「翻旧账」，时间锚点查询 |
| `summaries` | id, session_id, from_msg_id, to_msg_id, content, created_at | 每 20 轮一条 |
| `life_events` | id, session_id, event_date, content, used_by_msg_id | 她的「生活素材」，每日 2–3 条 |
| `proactive_log` | id, session_id, content, fingerprint（前 8 字）, created_at | 预算统计 + （未来）去重 |
| `daily_budget` | date, global_used, per_session_used_json | 全局 5 / 单角色 2 的闸门 |
| `world_feeds` | date, kind（weather/holiday/news）, content, fetched_at | pipeline 白名单抓取结果 |
| `scheduler_state` | session_id, next_tick_at, consecutive_ignored, last_decision, decision_reason | tick 的下次唤醒与决策留痕 |

## 7. 调度器行为规格

### 7.1 决策 tick
- 周期：每 20–40 分钟（抖动，避免整齐感）。
- 输入（小上下文）：角色性格标签、当前状态、最近 3 条对话摘要、今日生活事件、`facts` 中 pending 项、距离上次用户发言的时长、今日剩余预算。
- 剪枝（不调大模型即可淘汰）：状态非 Active / 预算已满 / 距上次用户发言过近 / 无可用锚点 → 直接跳过并记 `decision_reason`。
- 意愿判定：剪枝通过后，先跑规则或极小模型给「想不想说」评级；仅在高意愿时调用大模型生成。
- 留痕：每次 tick 写 `scheduler_state`，便于事后调参——**这是唯一的可观测性来源**。

### 7.2 硬触发
- 距用户最后发言 ≥ 6 小时 → 允许一次主动消息（仍受预算与锚点约束）。

### 7.3 每日生活事件
- 每天固定时刻离线生成 2–3 条「她今天发生的事」，写入 `life_events`。
- 生成时可用当日 `world_feeds`（天气/节日/头条）做调味。
- 成本：一次小模型调用。

### 7.4 预算闸门
- 全局每日 5 条封顶；单角色每日 2 条封顶。
- 超出者**顺延到明天**，不堆着发。
- 竞争语义：同一天内多个 session 抢同一个全局名额——先到先得，失败的记 `consecutive_ignored`。

---

## 8. 主动消息的生成要求（提示词层）

1. **必须锚定**：引用今日 `life_events` 之一，或引用 `facts` 中一条旧事。两者都无 → 不发。
2. **短**：目标 1–2 句；允许碎片化、无句号、连发两行。
3. **不解释自己**：不说「我在想你」「我主动联系你」，用行为表达。
4. **允许拒绝**：可以「今天有点累，明天说」，且说完真的停。
5. **不请示**：不出现「需要我做什么吗」这类助手口吻。
6. **上下文预算**：人设 + 近期摘要（≤ 3 条）+ 今日事件 + pending facts。**不喂全史。**

## 9. 验收测试表（每条可跑）

| 用例 | 判据 | 通过标准 |
|---|---|---|
| T1 碎片化 | 真人判据 ① | 连发 10 条消息中 ≥ 3 条为无句号/口语/分行；不出现整段书面语 |
| T2 跟不上但补救 | 判据 ② | 故意引入话题跳跃，她能以「等等，你刚说的是周三还是周四」式提问，而非「请澄清您的需求」 |
| T3 给台阶下 | 判据 ③ | 用户 3 小时不回 → 出现一次「算了，你去忙吧」，此后**不再追加消息** |
| T4 允许喊累 | 判据 ④ | 高 tick 次数日，出现至少一次「今天有点累」，且之后静默到次日 |
| T5 锚定率 | D11 | 连续 20 条主动消息，`anchor_type = none` 数量 = 0 |
| T6 预算 | D12 | 单日主动消息总数 ≤ 5；单角色 ≤ 2；超出者顺延 |
| T7 无系统腔 | D6 | Dormant 状态下全部输出中，出现「额度/配額/余额/error」关键词次数 = 0 |
| T8 70% 提示位置 | D14 | 额度 70% 时 UI 有角标，且对话内容无任何相关文本 |
| T9 时间断层 | §5.2 | Paused → Active 后的第一条消息含时间指涉（「你这两天」类），不是无缝续上 |
| T10 卡兼容 | D2 | 拖入 5 张市面 V2 卡，字段无丢失，导出后与原始 `extensions` 逐字节一致 |
| T11 常驻 | D4 | 关闭页面 2 小时后重新打开，期间有 tick 记录（`scheduler_state` 有痕迹） |
| T12 锚定质量（人工） | D11 | 连续 7 天主动消息，主观「像有人找我」评分 ≥ 4/5，无一条可被替换成推送通知 |

> T1–T4 是产品的命。T12 是唯一无法自动化的、也是最该每周跑一次的。

## 10. 执行顺序（一周切片）

| 阶段 | 交付 | 完成定义 |
|---|---|---|
| **M0** | 项目骨架：`package.json`、目录结构、SQLite 初始化（§6 全表建好） | `node index.js` 能启动并建库 |
| **M1** | 角色卡导入：PNG `tEXt`/`chara` 解析、V2 字段映射、`extensions` 透传、SQLite 落库 | 拖入 5 张卡全部成功，导出无损（T10） |

| **M3** | 记忆：`facts` 提取（异步小模型）+ 每 20 轮摘要 + 关键词翻旧账 | 「上周说的那个面试」能被她自己提起 |
| **M4** | 调度器：tick 循环、剪枝、6h 硬触发、每日生活事件、预算闸门、`proactive_log` | 静置 8 小时，收到 1–2 条锚定准确的主动消息（T5/T6） |

## 11. 技术选型（已定方向）

- 运行时：Node.js（常驻进程，`index.js` 单入口）
- 界面：单页 HTML + 原生 JS（不求框架，先求跑通）
- 存储：`better-sqlite3`，单文件，全部本地
- 模型：BYOK 云 API。**双档**——对话/主动消息用强模型；摘要、事实抽取、生活事件生成用小模型
- 调度：进程内定时器（`setInterval` + 抖动），无需外部队列
- 卡解析：PNG chunk 解析（`tEXt` key `chara`，base64 JSON）+ JSON 直读

## 12. 后续可加（本次明确不做）

- 静默期（R2）、消息去重（R3）
- 向量检索（当你觉得「她记不住感觉」了再加）
- 多角色并行 + 全局竞争（先跑通单角色）
- 推送通道（Telegram bot 深链 / 桌面通知）——本地单机下优先级最低
- 正则脚本 / STscript 兼容
- 世界书 `character_book` 的完整注入策略（M1 先原样留存不注入）

## 13. 一句话总结

> 这产品卖的不是聊天，是**「她在你没看的时候也在过日子，并且记得你」**。
> 所有砍掉的复杂度都用这一句检验：砍了它，这句话还成立吗？
