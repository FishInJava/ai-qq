# 0001: 单进程单入口，页面纯消费者，SQLite 单写入者

**Status:** accepted

**Date:** 2026-02-11

**Context:** 产品承诺的是"关掉窗口她还在过日子"。任何把状态放在浏览器、或让页面参与调度的做法都会直接摧毁产品承诺：用户关页面、锁屏、切换浏览器标签都会变成"她死了"。同时数据只有一份（一个本地库），多写者会引入锁竞争与丢失更新，而用户规模是 1 人 1 进程，引入服务化分层只是给自己制造部署成本。

**Decision:**

1. 唯一常驻体是一个 Node 进程（`src/index.js` 单入口），同时承担 HTTP 服务、调度宿主、SQLite 唯一写入者。
2. 页面（`web/`）只通过 HTTP/SSE 消费，**不写库、不持有定时器、不缓存权威状态**。刷新/关闭/崩溃不改变任何调度状态。
3. 所有 SQL 收敛在 `src/store/repo/*`，业务模块拿不到 `db` 句柄；跨表写操作必须经 `store.tx()`（`BEGIN IMMEDIATE`）。
4. 调度只有一个实现 `runTick(sessionId, trigger)`；定时器只是调用它的壳，不承载决策。

**Consequences:**

- 好处：断电/崩溃恢复只需保证一个进程与一个库一致；页面可以随时换技术栈而不动业务；测试只需起一个真实进程。
- 代价：所有并发收敛到进程内（内存互斥 + 单写入者），SQLite 的写并发上限就是产品的上限——对单用户完全够，对多用户不成立。
- 放弃：Express/Koa 等框架、任何"后端 + 前端分离部署"形态、多进程 worker 池。
- 影响面：`runtime`、`store`、`http`、`session`、`schedule`；新增写库路径时必须走 repo。
